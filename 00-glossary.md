## Версии и релизы

**Game drop** — формат релизов с 2025 года: несколько небольших обновлений в год вместо одного крупного. Каждый drop получает имя (`Wilderness Bound`) и версию.

**Календарное версионирование (26.x)** — с 2026 года версия = `YY.N`, где `YY` — год, `N` — номер drop'а. `26.3` — третий релиз 2026 года. Последняя версия старой схемы — `1.21.11`. Снапшоты тоже переименованы: `26.3-snapshot-1` вместо `25w41a`.

**Data version / resource pack format / data pack format** — внутренние номера форматов. Нужны, чтобы понять, совместимы ли ваши datapack/resourcepack с версией игры. Для 26.3: data version `5023`, resource pack format `97.1`, data pack format `121.0`.

**Java-версия** — минимальная версия JDK для запуска и сборки. `1.17–1.20.4` — Java 17, `1.20.5–1.21.11` — Java 21, `26.x` — Java 25. Несовпадение даёт `UnsupportedClassVersionError` ещё до запуска игры.

## Лоадеры

**Loader (загрузчик модов)** — слой, который находит моды, грузит их и применяет изменения к игре. Основные: Forge, NeoForge, Fabric, Quilt.

**Fabric Loader** — минималистичный лоадер. Не содержит большого API: за удобства отвечает отдельный `Fabric API`. Использует Mixin как основной механизм вмешательства.

**Quilt** — форк Fabric с собственным loader'ом и расширениями; совместим с большинством Fabric-модов.

**NeoForge** — форк Forge, появившийся после 1.20.1. С 1.20.2 — основная площадка «Forge-семейства». Отказался от старых coremod-механизмов в пользу Mixin, но сохранил свои события, реестры и Access Transformers.

**Legacy-лоадеры** — проекты для старых версий: **Legacy Fabric** (1.8–1.12), **Ornithe** (точные mappings и API для старых версий), **Babric** (Beta 1.7.3), **Rift** (1.13, исторический).

**ModLauncher** — launch-библиотека Forge/NeoForge, которая грузит моды до старта игры и даёт им возможность трансформировать классы. Важно: Mixin в Forge/NeoForge работает через неё, а не через java agent.

**Sinytra Connector** — слой совместимости, позволяющий запускать Fabric-моды на NeoForge. Не серебряная пуля: миксины в чужие моды и API-несовместимости всё равно ломаются.

**Architectury** — абстракция над лоадерами: один общий код + тонкие платформенные модули. Полезна, когда мод должен выйти на Fabric и NeoForge одновременно.

**MultiLoader** — паттерн «один репозиторий, несколько source set'ов» без Architectury. Больше контроля, больше ручной работы.

## Сборка

**Gradle** — система сборки, используемая всей экосистемой. Начиная с 26.x требуется **Gradle 9.2+** (Loom) и **9.1+** (ModDevGradle).

**Loom** — Gradle-плагин Fabric. С версии 1.14 расколот:
- `net.fabricmc.fabric-loom` — для необфусцированных версий (26.x+), ничего не ремапит;
- `net.fabricmc.fabric-loom-remap` — для обфусцированных (до 1.21.11);
- `fabric-loom` — старый ID для обратной совместимости.

**ForgeGradle (FG)** — исторический плагин Forge. Актуален для 1.20.1 и старее; для новых версий Forge/NeoForge используется ModDevGradle или NeoGradle.

**ModDevGradle (MDG)** — официальный плагин NeoForge. Версия 2.x сильно поменяла API: моддинг включается явно, `loadedMods` вместо `mods`, `neoForge.ideSyncTask`. Рекомендуется для новых проектов.

**NeoGradle (NG)** — альтернативный плагин NeoForge (7.x), ближе к классическому ForgeGradle-опыту.

**RetroFuturaGradle (RFG)** — плагин для legacy Forge (1.7.10–1.12.2) с MCP mappings. Стандарт для GTNH-подобных проектов.

**Unimined** — Gradle-плагин для мульти-версионных и мульти-лоадерных проектов, включая очень старые версии. Позволяет одной кодовой базой собирать несколько target'ов.

**VanillaGradle** — плагин, дающий «чистую» ваниль без лоадера. Полезен для серверных плагинов и тестов.

**MixinGradle** — исторический плагин, добавлявший annotation processor для refmap. В современных Loom/MDG встроен и по умолчанию не нужен.

**NeoForm** — форк MCP, который готовит компилируемые исходники Minecraft для NeoForge. Версии вида `26.1-1`.

**NeoForm Runtime (NFRT)** — рантайм, который выполняет пайплайн NeoForm (декомпиляция, патчи, ремап). В MDG 2.x настройки вынесены на верхний уровень.

**Datagen (data generation)** — генерация JSON-ассетов и данных (модели, рецепты, теги, loot tables) кодом во время сборки. Убирает ручное редактирование сотен JSON-файлов.

## Mappings и обфускация

**Обфускация** — переименование классов/методов/полей в бессмысленные имена (`a`, `b`, `func_12345_a`). Применялась Mojang **до 1.21.11 включительно**.

**Деобфускация** — обратный процесс. С **26.1** игра поставляется деобфусцированной: официальные имена Mojang доступны в рантайме.

**Mappings** — таблица соответствия «имя в рантайме ↔ читаемое имя».

**Mojmap (official mappings)** — официальные mappings Mojang. С 1.17 использовались в Forge/NeoForge, с 26.1 стали именами рантайма.

**Yarn** — mappings Fabric. Существовали только для обфусцированных версий; для 26.x неприменимы.

**MCP (Mod Coder Pack)** — исторические mappings Forge с именами вида `func_XXXXXX_a`. Использовались до 1.16.5 включительно.

**SRG / TSRG** — промежуточные имена Forge, в которые ремапились моды на старых версиях.

**Intermediary** — стабильный namespace Fabric (`class_XXXX`, `method_XXXX`, `field_XXXX`). Мод компилируется в named, а в рантайме работает через intermediary, чтобы не зависеть от версии.

**Remapping** — перевод ссылок из одного namespace в другой. Выполняется на этапе сборки (TinyRemapper) или рантайма.

**TinyRemapper** — инструмент Fabric для ремапа. С Loom 1.12+ ремапит и сами миксины, из-за чего refmap перестал быть обязательным.

**Refmap (reference map)** — JSON-файл, который annotation processor генерировал для миксинов: переводил «мягкие ссылки» в аннотациях (`method = "..."`, `@At(target = "...")`) в обфусцированные имена. **Не нужен** на Fabric с новым Loom и **не нужен** на NeoForge/26.x.

**Parchment** — набор параметров и javadoc'ов поверх Mojmap. После деобфускации 26.1 стал опциональным: имена параметров теперь приходят с игрой.

**Access Widener (AW)** — файл Fabric, расширяющий доступ (`accessible`, `extendable`, `mutable`) к классам/методам/полям. С Fabric Loader 0.18 и Loom 1.12 переименован в **class tweaker** (`*.classtweaker`, заголовок `classTweaker v1 official`), но имена свойств в build-скрипте и `fabric.mod.json` остались прежними. Работает и на 26.x, потому что не связан с обфускацией.

**Access Transformer (AT)** — аналог AW в Forge/NeoForge.

**Interface injection** — механизм NeoForge, позволяющий объявить, что ванильный класс реализует ваш интерфейс, без миксина.

## Mixin

**Mixin** — фреймворк SpongePowered для вмешательства в байткод чужих классов на этапе загрузки. Позволяет добавлять поля, методы, интерфейсы и вставлять код в существующие методы, не редактируя исходники.

**Mixin-класс** — обычный Java-класс с `@Mixin(Target.class)`, который «подмешивается» к цели. Не инстанцируется напрямую.

**Mixin config** — JSON (`*.mixins.json`) со списком миксинов, `compatibilityLevel`, `refmap`, `priority`, `plugin`.

**compatibilityLevel** — версия Java, под которую компилируется миксин: `JAVA_17`, `JAVA_21`, `JAVA_25`. Должна соответствовать версии игры, иначе Mixin откажется загружаться.

**Priority** — порядок применения миксинов к одной цели. По умолчанию 1000; меньше — раньше.

**MixinExtras** — библиотека-компаньон (LlamaLad7), добавляющая «цепляющиеся» инъекторы и язык выражений. Поставляется с NeoForge и современным Fabric Loader.

**`@Shadow`** — объявление поля/метода цели, к которому нужен доступ из миксина. Компилятор видит заглушку, Mixin подставляет реальный член.

**`@Unique`** — пометка «это поле/метод существует только в миксине», чтобы избежать конфликта имён с другими модами.

**`@Final` / `@Mutable`** — работа с `final`-полями: `@Final` запрещает запись, `@Mutable` разрешает менять финальное поле.

**`@Accessor` / `@Invoker`** — генерация геттеров/сеттеров и вызовов для приватных членов цели без написания `@Shadow`-методов вручную.

**`@Overwrite`** — полная замена метода. Ломает все остальные миксины на этом методе; использовать только когда альтернатив нет.

**Duck interface** — интерфейс, который миксин «надевает» на ванильный класс, чтобы другие части кода могли привести объект к нему и получить доступ к добавленному состоянию.

## Инъекции и байткод

**Байткод** — инструкции JVM, с которыми работает Mixin. Декомпилированный исходник — лишь приближение; для точной цели смотрят байткод.

**Descriptor** — сигнатура в формате `Lowner;name(Lparam;)Lret;`. Используется в `@At(target = ...)`.

**Injection point (`@At`)** — точка вставки: `HEAD`, `RETURN`, `TAIL`, `INVOKE`, `INVOKE_ASSIGN`, `FIELD`, `NEW`, `CONSTANT`, `JUMP`, `LOAD`, `STORE`. `LOAD`/`STORE` работают только с `@ModifyVariable`.

**Инъектор (injector)** — аннотация, описывающая, *что именно* сделать в точке: `@Inject`, `@Redirect`, `@ModifyArg`, `@ModifyVariable`, `@WrapOperation` и т.д.

**`ordinal`** — номер совпадения, если целевая инструкция встречается в методе несколько раз. Хрупкий: любое изменение кода сдвигает нумерацию.

**`@Slice`** — ограничение области поиска между двумя якорями. Тоже позиционный и хрупкий; часто заменяется `@Expression`.

**`shift` / `by`** — сдвиг точки вставки на N инструкций до/после якоря. Признак того, что цель выбрана неточно.

**`@Expression` + `@Definition`** — язык MixinExtras для описания цели структурно: «вызов такого метода с таким аргументом», «сравнение поля с константой», «`instanceof` такого типа». Устойчивее к рефакторингу, чем `ordinal`/`@Slice`.

**`@Local`** — MixinExtras-способ захватить локальную переменную. На 26.x можно по имени, до 26.1 — только по типу/ordinal/индексу.

**`@WrapOperation`** — обёртка вызова/поля/`instanceof` с возможностью вызвать оригинал через `original.call(...)`. Цепляется с другими модами, в отличие от `@Redirect`.

**`@ModifyExpressionValue`** — изменение значения выражения (результата вызова, поля, константы) без замены самого вызова.

**`@ModifyReturnValue`** — изменение возвращаемого значения метода. Часто заменяет `@Inject(at = RETURN)` + `cir.setReturnValue`.

**`@WrapWithCondition`** — условное выполнение void-вызова или записи в поле.

**`@WrapMethod`** — обёртка всего метода (try/catch, замеры, логирование) с вызовом оригинала.

**Synthetic / bridge / lambda** — члены, которых нет в исходнике: лямбды (`lambda$foo$0`), мостовые методы после generics, поля `this$0`. Декомпилятор их часто скрывает, а миксину иногда нужны именно они.

**`INVOKEDYNAMIC`** — инструкция создания лямбды/строковой конкатенации. В `@At` её цель указывается иначе, чем у обычного `INVOKE`.

## Данные и реестры

**Data Components (1.20.5+)** — замена NBT-тегов предмета на типизированные компоненты (`minecraft:damage`, `minecraft:enchantments`). `ItemStack` теперь хранит `DataComponentPatch`.

**`DataComponentPatch`** — набор изменений компонентов относительно дефолтных для предмета.

**`ItemStackTemplate` (26.1+)** — иммутабельный «черновик» стака: предмет + количество + patch. Нужен там, где нельзя создать `ItemStack` до загрузки реестров (рецепты, advancements, data-файлы).

**`Codec` / `MapCodec` / `StreamCodec`** — системы (де)сериализации Mojang: JSON/NBT и сеть соответственно. С 1.20.5+ почти все игровые объекты описываются кодеками.

**`Registry` / `Holder` / `HolderLookup.Provider`** — реестры и ссылки на их элементы. `Holder` позволяет ссылаться на элемент реестра до его инициализации; в 1.20.5+ реестры стали datapack-driven.

**`ResourceLocation` / `Identifier`** — идентификатор `namespace:path`. В 1.21.11 Mojang переименовал класс в **`Identifier`** (дань уважения Yarn), поэтому в 26.x он называется `net.minecraft.resources.Identifier`; сигнатуры методов те же. Окружение вокруг него (реестры, компоненты) заметно поменялось.

**`Level` / `BlockEntity`** — современные имена `World` и `TileEntity` (переименованы в 1.18).

## Рендер

**`PoseStack`** — стек трансформаций (бывший `MatrixStack`). Переименован в 1.17.

**`GuiGraphics`** — контекст отрисовки GUI (с 1.20). В 26.1 переименован в **`GuiGraphicsExtractor`**, а методы экранов — в `extractRenderState`, `extractBackground`, `extractLabels`.

**`ItemModel` (1.21.4+)** — новая система моделей предметов: `assets/<ns>/items/*.json` вместо `models/item/*.json`.

**`RenderPipeline` (1.21.5+)** — описание состояния GPU-пайплайна. Часть большого рефакторинга рендера 1.21.5–26.x.

**Baked quad / `MutableQuad`** — геометрия для отрисовки моделей. В NeoForge 26.1 появился `MutableQuad` для удобного построения и правки квадов.

## Отладка и тесты

**`-Dmixin.debug`** — набор системных свойств Mixin. Самые полезные: `mixin.debug.export=true` (дамп пропатченных классов в `.mixin.out/class`), `mixin.debug.verbose=true`, `mixin.debug.countInjections=true`, `mixin.checks=true`, `mixin.dumpTargetOnFailure=true`.

**MixinTrace** — мод, который добавляет в стектрейсы информацию о миксинах, участвовавших в вызове. Сильно упрощает чтение крашей.

**Crash Assistant** — мод, разбирающий crash-report и показывающий вероятную причину и виновника.

**Hotswap** — подмена классов в работающей JVM. Обычный HotSpot умеет менять только тела методов; для структурных изменений нужны DCEVM/JBR и флаги вроде `-XX:+AllowEnhancedClassRedefinition`.

**JFR (Java Flight Recorder)** — встроенный профайлер JVM. Даёт CPU/аллокации/локи без внешних агентов.

**spark** — популярный профайлер для Minecraft (Fabric/Forge/NeoForge), умеет CPU, memory, lag-spike анализ.

**GameTest** — фреймворк Mojang для автоматических тестов игровой логики в мире. Доступен модам через лоадеры.

**MC-Runtime-Test** — инструмент для запуска клиента Minecraft в CI и прогона smoke/GameTest-сценариев.

**HeadlessMc** — CLI-лаунчер Minecraft, умеет запускать клиент без GPU/дисплея. Удобен для CI и автоматизации.
